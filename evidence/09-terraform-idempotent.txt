A second `terraform plan` immediately after apply:

  $ terraform plan -detailed-exitcode
  No changes. Your infrastructure matches the configuration.
  exit code: 0        (0 = no changes, 1 = error, 2 = drift)

This is the check that catches the two-writers bug. azurerm_subnet also accepts
a network_security_group_id inline. Set it there AND declare
azurerm_subnet_network_security_group_association and this plan is never empty:
each apply, one writer sets the field and the other clears it, forever.

Exit code 0 is the proof that exactly one resource owns that field.
